# 接单台（ops）平台化信息架构

日期: 2026-11-17  
状态: 已确认  
应用: `com.ibox.fire.ops`（`ibox-fire-android/ops`）

## 目标

把现有「账号 / 开火 / 日志」改成以**平台**为轴的结构：账号池与登录管道挂在平台下；科技功能（抢合等）挂在「平台」页展开后；为后续多平台扩展留骨架。

## 底栏

| Tab | 原名 | 职责 |
|-----|------|------|
| 0 | 账号 | 平台列表 → 账号池 + 登录管道 |
| 1 | **平台**（原「开火」） | 平台列表 → 科技功能（iBox 抢合等） |
| 2 | 日志 | 全部日志 + 按账号分区 |

## 平台骨架（P0）

列表固定三项（可配置扩展）：

1. **iBox** — 本版可用（账号登录/验活/H5/抢合）
2. **NewBee** — 占位「即将支持」
3. **Topstar** — 占位「即将支持」

后续可加 iBpro、盯盒等，不改底栏结构。

数据模型：账号增加 `platformId`（如 `ibox` / `newbee` / `topstar`）。存量账号默认 `ibox`。

## 账号页

### 展开顺序（已确认）

1. **账号池**（上）
2. **登录管道**（下：短信 / 贴 Token / 云端同步）

### 账号池

- 勾选（供平台页抢合使用；仅同平台号）
- **一键验活**（当前展开平台下全部账号）
- 单号：**验活** · **H5** · **复制token描述** · **删**
- 「复制token描述」文案；剪贴板两行：
  ```
  token=<jwt>
  deviceId=<uuid或空>
  ```
- **H5**：P0 仅 iBox，用该号 token(+deviceId) 打开官方 H5（对齐用户版 `OfficialH5Activity`）；其它平台按钮禁用或提示未接

### 登录管道

- 逻辑沿用现有短信极验 / 贴 Token / 云端拉取推送
- 新号写入时带上**当前展开平台**的 `platformId`

## 平台页

- 同三平台列表；展开 **iBox** → 迁入现有抢合 UI（活动/通道/材料/开火时间/模式/开始）
- 开火目标账号 = 账号页中 **该平台且已勾选** 的账号；无勾选时提示去账号页勾选
- NewBee / Topstar 展开仅占位文案，不进抢合

## 日志页

- 筛选芯片：**全部** + **每个账号**（去掉独立「系统」芯片）
- 系统行（原 `*`）混入「全部」交织时间线
- 点账号芯片只看该号日志

## 非目标（本版不做）

- NewBee / Topstar 真实登录与科技
- 计费、客户分房间、口令自动开火
- 改云端 QQ 上号协议字段（可先本地打平台标；云端同步后默认 ibox）

## 实现落点（指导）

- UI: `ops/.../ui/OpsScreens.kt`
- 状态: `OpsViewModel.kt` / `OpsUiState`（tab 文案、平台展开态、`platformId` 过滤）
- 账号: `OpsAccount` + `AccountStore`
- H5: 复用或轻量桥接 `app` 模块 `OfficialH5Activity`（若 ops 独立 APK 不便依赖，则 ops 内嵌等价 WebView 打开逻辑 / 显式 Intent 到同签名用户版——实现计划里选定一种）
- 验活: 已有 `SiteApi.verifyToken`，批量串行/有限并发即可

## 验收

1. 底栏显示「平台」而非「开火」
2. 账号页展开 iBox：池在上、登录在下；复制含 deviceId；验活可用；H5 能开
3. 平台页展开 iBox 可见抢合并可用已勾选号开火
4. NB/TS 可见但不可用
5. 日志仅「全部」+ 账号芯片
